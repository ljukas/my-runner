# Android Stage 7 — Release Pipeline

> Built in one session on `ll/android-stage-7` (worktree `.claude/worktrees/android-stage-7`), branched from `ll/android-stage-6` (PR #68). Like stage 6 there was no separate handoff: the design was settled in-session and is recorded here, with the "As built" section at the end. Read with [ADR 0025](../../adr/0025-android-staged-migration.md) (row 7 + the 2026-09-27 amendment), and the amendments of the same date to [ADR 0012](../../adr/0012-release-please-fingerprint-gated-releases.md) (release), [ADR 0001](../../adr/0001-local-first-maestro-e2e-testing.md) (the lane) and [ADR 0016](../../adr/0016-text-first-maestro-selectors.md) (selectors).

**Goal:** a release builds, updates and submits the Android app like the iOS one, and every PR runs the Maestro flows that apply to Android on an emulator. iOS unchanged.

**Spec:** ADR 0025 row 7 ("`eas.json` Android profiles, Play service account, `.eas/workflows/deploy-production.yml`'s existing Android jobs go live (ADR 0012), an `e2e-android` GitHub Actions lane with Maestro on the emulator (ADR 0001).").

## 1. Verified facts that shaped the design (2026-09-27)

- `deploy-production.yml` already carried the full Android path (get-build → OTA or build → approval → submit); only the config it resolves was missing: `eas.json` had no Android keys and `submit.production` was `{}`.
- EAS docs: `submit.production.android` takes `track` / `releaseStatus`; the Play service-account key can live in EAS credentials, so `eas.json` needs no path (the workflow runs on EAS servers anyway); Android credentials are only generated by an interactive build; a profile without `environment` resolves to `production` (store), `development` (dev client) or `preview`; `android.withoutCredentials` exists and is Expo's own E2E example.
- ADR 0019's variant suffix applies to both platforms, so the e2e build is `se.lukaslindqvist.runbro.e2e` on Android too — no per-platform `appId`.
- Android onboarding has all four steps (the health primer shows "Your runs, in Health Connect"); both drafted architectures had assumed three.
- The Play developer account (`8846992213517983364`) is under verification, so the app cannot be created yet.

## 2. Decisions (settled 2026-09-27)

1. **Track:** `internal`, `releaseStatus: draft`, following iOS's TestFlight; production later.
2. **Signing:** EAS-generated upload key, Play App Signing on.
3. **Maps key:** one key, an EAS environment variable in `production` + `preview`, restricted by the upload and app-signing SHA-1s.
4. **`preview` builds an APK** for sideloading.
5. **E2E scope (option B):** the full lane plus the flows that transfer; Android's permission, Settings and Health Connect flows later.
6. **`e2e-android` becomes required** like `e2e-ios` — after its first green run.
7. **`e2e-refresh` stays iOS-only**; Android targeted flows are run by hand.
8. **Play policy paperwork** goes into a checklist.
9. **Architecture "C"** (of a minimal and a clean draft): flows stay flat and shared, iOS-only ones tagged `ios-only`; platform differences confined to the launch helper's permissions and widened anchors; the E2E profile keeps its name and gains Android keys; a sibling `e2e-android` job, not a matrix (a matrix renames the required `e2e-ios` context); no `package.json` script changes.

## 3. Task plan (as executed)

1. Baseline fingerprints, both platforms × three variants.
2. `eas.json`: `preview.android.buildType: apk`, `e2e-simulator.android.withoutCredentials`, `submit.production.android`; confirm the resolved profile with `eas config`; re-measure.
3. Maestro: `ios-only` tags; platform-branched permissions in `launch-and-onboard.yaml`; widened anchors.
4. The `e2e-android` job (after review: both jobs on one composite action, `.github/actions/e2e-native-app`, and one `build-e2e-app.sh <platform>` script).
5. Local proof of the CI path: `eas build --local` → APK → emulator → the Android flow set; repack onto it.
6. Gates: `bun run lint && bun run typecheck && bun run typecheck:android && bun test`; `actionlint`.
7. iOS regression flows on a fresh `e2e-simulator` build.
8. Checklist, ADR amendments, AGENTS.md.
